Como ler o modelo

O aluno pode fazer vários empréstimos. Cada empréstimo pode incluir vários equipamentos; a tabela ITEM_EMPRESTIMO resolve esse relacionamento N:N e guarda dados específicos de cada item.

Ver esquema SQL
CREATE TABLE Aluno (
  id_aluno INTEGER PRIMARY KEY,
  nome VARCHAR(100) NOT NULL,
  email VARCHAR(150) UNIQUE NOT NULL
);

CREATE TABLE Categoria (
  id_categoria INTEGER PRIMARY KEY,
  nome VARCHAR(60) UNIQUE NOT NULL
);

CREATE TABLE Equipamento (
  id_equipamento INTEGER PRIMARY KEY,
  id_categoria INTEGER NOT NULL REFERENCES Categoria(id_categoria),
  descricao VARCHAR(120) NOT NULL,
  numero_patrimonio VARCHAR(40) UNIQUE NOT NULL
);

CREATE TABLE Emprestimo (
  id_emprestimo INTEGER PRIMARY KEY,
  id_aluno INTEGER NOT NULL REFERENCES Aluno(id_aluno),
  data_retirada DATE NOT NULL,
  data_prevista DATE NOT NULL,
  status VARCHAR(20) NOT NULL
);

CREATE TABLE Item_Emprestimo (
  id_emprestimo INTEGER REFERENCES Emprestimo(id_emprestimo),
  id_equipamento INTEGER REFERENCES Equipamento(id_equipamento),
  condicao_retirada VARCHAR(120),
  condicao_devolucao VARCHAR(120),
  PRIMARY KEY (id_emprestimo, id_equipamento)
);

04 / CONCEITOS EM FOCO

Decisões que sustentam bons dados

Entidade e atributo

Entidades representam objetos relevantes do domínio, como Aluno e Equipamento. Atributos descrevem suas propriedades.

Chaves

A PK identifica cada registro. A FK referencia um registro de outra tabela e mantém a integridade referencial.

Cardinalidade

1:N significa que um registro de um lado pode se associar a muitos do outro. N:N é implementado com uma tabela associativa.

Normalização

As formas normais reduzem redundância e anomalias de inserção, atualização e exclusão, respeitando dependências funcionais.
